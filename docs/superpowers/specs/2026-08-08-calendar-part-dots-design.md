# カレンダーの部位表示 + 月間バランス集計

日付: 2026-08-08

## 目的

カレンダーを見たときに「その日どの部位を鍛えたか」がわかるようにする。
狙いは記録の閲覧そのものではなく、**部位のバランスを見ながらトレーニングを組めること**。
「今月は脚が少ない」に気づけることがゴール。

## 決定事項

### 1. 部位を5つに整理

現行8部位（胸/背中/肩/腕/脚/腹/全身/有酸素）から **肩・全身・有酸素 を削除**し、
**胸・背中・腕・脚・腹** の5部位にする。

既存DBを確認したところ、削除する3部位は1件も使われていないためデータ移行は不要。

### 2. 部位カラー

| 部位 | 色 |
|---|---|
| 胸 | `#E23B2E` 赤 |
| 背中 | `#3F77A3` 青 |
| 腕 | `#8E5BC4` 紫 |
| 脚 | `#3FA34D` 緑 |
| 腹 | `#D94F8A` ピンク |
| その他 | `#A08A66` 灰茶 |

オレンジ系と黄色は使わない。「トレした日」のセル背景が `var(--orange)` のため、
その上に置くドットと紛らわしくなるのを避ける。

### 3. 「その他」の扱い

part が空、または既知の5部位のいずれにも一致しない値（旧自由入力の `腹筋` `腕立て伏せ` 等）は
すべて「その他」として灰茶のドット1つで表す。バランスパネルでは件数が0のとき行を出さない。

推測で `腹筋`→`腹` のように寄せることはしない（不正確なため）。

### 4. カレンダーのセル

日付の下に、その日に含まれる部位のドットを **PARTS の定義順** で表示する。

- 1日に複数の記録があっても、部位は**重複排除**して1つのドットにまとめる
- ドットは 11px の四角 + クリーム(`var(--paper)`)の縁。ドットが出るのは「トレした日」＝
  オレンジ背景のセルだけなので、縁だけで十分に分離できる
- ドット枠は `width: 85%`、ドットは `calc((100% - 2px) / 3)` + `aspectRatio: 1` で1行3個。
  最大6部位（5部位 + その他）でも 3+3 の2行に収まる
- **px 固定にしないこと。** `#phone` は `body`（`display: flex`）の項目で `flex-shrink` が
  効くため、414px 未満の画面ではセルが縮む（390px 画面でセル 44px → 34px）。px 固定だと
  そこでドットがセルからはみ出し、隣の週の行とぶつかる（grid gap は 5px しかない）。
  相対値なら 300px 幅まで 2行に収まる（実測: 414/342/320/300px すべてはみ出し 0）
- 従来の ★ マークはドットに置き換える（トレした日の判別はセル背景のオレンジが担う）

小さすぎると色が判別できない。`box-sizing: border-box` のため縁の 1px は内側に食い込む
（11px 指定で色の部分は 9px）点に注意。

**セル側で必要な指定（どれも欠かすと崩れる）:**

- `minWidth: 0, minHeight: 0` — グリッド項目の既定 `min-width/height: auto` はドットぶんまで
  広がる。`aspectRatio: 1` と組み合わさるとセルが 44px → 53px に膨らみ、7列で横に 30px はみ出す
- `padding: 0` — `<button>` の UA 既定 `padding: 1px 6px` が内容幅を 40px → 28px に削り、
  ドット枠の `width: 35px` が `maxWidth: 100%` で 28px に切り詰められて折り返し位置が狂う

### 5. 部位バランスパネル

下部の3カード（トレした日 / きろく数 / コイン）を、**表示中の月**の部位別集計に置き換える。

- 指標は **「その部位をやった日数」**（記録件数ではない）。バランスを見るには日数が適切
- 各行: 部位名（部位色）+ 横バー + 日数。バー幅は最大値に対する比率
- 5部位は0でも常に表示する（0の部位に気づけることが本来の目的なので）
- 「その他」行は件数が0のときのみ非表示
- 色付きの部位名が並ぶため、**このパネルが凡例を兼ねる**。別途凡例は置かない

### 5b. 背の低いビューポートでのスクロール

`#phone` は `max-height: calc(100vh - 48px)` なので、ウィンドウが低いとカレンダー画面の
描画領域が縮む。月ヘッダー(40) + バナー(103) + グリッド(343) + padding/gap(78) = 564px は
固定高なので、この時点で 491px の領域を超える。ルートが `overflow: hidden` だと**はみ出しが
切り捨てられ、スクロール手段もない**（実測: content 589px を 547px に切り取り）。

対応:

- カレンダー画面のルートを `overflow: auto` にして、収まらないぶんはスクロールで届くようにする
- 各ブロックに `flexShrink: 0` を付けて潰さない
- 下部パネル（バランス / 日別詳細）は `flex: 1` ではなく **`flex: "1 0 auto"`**。
  `flex: 1` は `flex-basis: 0` なので、余白がゼロだと高さ0に潰れてしまう。
  `1 0 auto` なら余白があれば伸び、なければ内容ぶんの高さを保つ

「きろく」画面は内容が可変（ログカードが縮む）ため、はみ出さない。変更不要。

置き換えで失われる情報はない: 日数は上のバナー、コインはトップバーに既に出ている。
「きろく数」のみ表示場所がなくなるが、バランスパネルの方が目的に直結する。

日を選択したときは従来どおりバランスパネルの位置に「その日のきろく」詳細が出る（変更なし）。

### 6. 記録シートの部位チップ

選択中のチップの背景を、オレンジ固定ではなくその部位の色にする。
入力時に色と部位の対応が自然に身につくため。

## 実装

### 変更するファイル

| ファイル | 変更 |
|---|---|
| `static/parts.jsx` | **新規**。部位定義・色・集計ヘルパー |
| `static/index.html` | `parts.jsx` の script タグを追加（`homeInput.jsx` より前） |
| `static/homeInput.jsx` | ローカルの `PARTS` 定義を削除して共通定義を使う。チップを部位色で塗る |
| `static/calendar.jsx` | セルにドット行を追加。3カードを `PartBalance` に置き換え |

### `static/parts.jsx` が公開するもの

- `window.PARTS` — `["胸","背中","腕","脚","腹"]`
- `window.PART_COLORS` — 部位名 → 色。`その他` のキーも含む
- `window.OTHER_PART` — `"その他"`
- `window.dayParts(entries)` — その日の entry 配列 → 表示順に並んだ部位名の配列（重複排除、未知/空は `その他` に集約）
- `window.monthPartTally(history)` — `{日: entries[]}` → `[{part, days}]`（PARTS順、末尾に `その他`）

境界が明確な純粋関数のみなので、カレンダーと記録画面のどちらからも副作用なく使える。

### バックエンド

**変更なし。** `/api/status?month=` が既に対象月の全 entry を `part` 付きで返しているため、
集計はクライアント側で `history` から計算できる。

## 検証

- Go は無変更なので `go test ./...` が引き続き通ること
- フロントにテスト基盤がないため、アプリを起動してブラウザで実際に確認する:
  - 複数部位の日にドットが正しい色・順序で出る
  - `腹筋` / `腕立て伏せ` の日が「その他」の灰ドットになる
  - バランスパネルの日数が実データと一致する
  - 月を移動するとバランスパネルもその月の集計になる
  - 日をタップすると従来どおり詳細に切り替わる
